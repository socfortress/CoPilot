Talon is the AI SOC analyst [SOCFortress](https://www.socfortress.co/) builds for CoPilot. It runs as a separate service next to CoPilot (a Docker Compose stack called **talon-analyst**) and does three things:

- **Investigates alerts** that CoPilot sends it, and writes a structured report, IOCs and the job status back into CoPilot.
- **Chats** with your analysts on the AI Analyst page.
- **Remembers** what it learns, per customer.

CoPilot stays the database of record and the only UI. Talon reads your SIEM and endpoints through read-only accounts, and anything that changes something (an alert, an endpoint) goes through CoPilot.

## What it does

- **One investigation per alert.** Each alert CoPilot sends is investigated on its own, never batched with other alerts or other customers.
- **Code runs the pipeline, the model does the judgement.** Loading the alert, tenant scoping, write-back, restoring anonymized values and memory writes are done in code. The model investigates and writes the report.
- **Shadow, then live, per customer.** A new customer's reports stay inside Talon until you have compared them and switched that customer to live.
- **Per-customer anonymization.** Usernames, hostnames, email addresses and internal IPs reach the model as tokens, and are restored in the report for that customer only.
- **Per-customer memory** in MemPalace: past outcomes, likely false positives and the lessons your analysts teach it.
- **Threat intel lookups** for public indicators (optional).
- **Chat with threads scoped to one customer**, when the **Talon v2** setting is on.
- **Actions only with a human approval.** In chat, Talon proposes; CoPilot shows exactly what will run and runs it after an approver says yes.
- **Per-customer automation levels**, off by default.
- **Cost tracking and budgets** per customer and per user.
- **A health dashboard** on the AI Analyst page.

## How an investigation runs

Talon investigates only what CoPilot sends it. It has no scheduled sweep of its own.

<Steps>
  <Step title="CoPilot sends the alert">
    CoPilot calls Talon's `POST /investigate` when:

    - a new alert arrives for a customer whose **AI trigger** is on (**Customers → *customer* → AI Triggers**; off by default);
    - an analyst clicks **Investigate with AI Analyst** on an alert;
    - a Customer Portal user requests an analysis (if you allow it, see [Customer Portal](#customer-portal) below);
    - an analyst replays a report with another template ([review workflow](/power-features/ai-analyst-review)).

    Talon answers at once with a job id and queues the work. A repeat request for an alert that is already queued, running or was just investigated returns the existing job instead of starting another.
  </Step>
  <Step title="It is queued durably">
    The queue lives in Postgres, so a restart loses no queued or running investigation. A few run at once (three by default). Each run has hard limits on time, model requests, tool calls and tokens; a run that hits one ends **failed**, with the reason on the job.
  </Step>
  <Step title="It gathers the evidence">
    In code, before the model starts: the alert, its asset and customer from CoPilot (through a read-only database user), the raw event from the Wazuh indexer (only from that customer's verified indices), the Wazuh agent's context, and earlier reports on the same alert, asset or rule.
  </Step>
  <Step title="It picks a template">
    One of 18 investigation templates (Sysmon events, Windows Defender, Autoruns, Sigcheck and others), chosen from the event's rule groups and fields, or the one an analyst asked for on a replay.
  </Step>
  <Step title="The model investigates">
    The analyst agent gets the evidence and the template's guidance, uses read-only tools (SIEM queries bound to the customer, Wazuh, Velociraptor, threat intel, memory) and returns a typed report: a summary, a severity, the full report (alert summary, raw event details, IOC analysis, SIEM correlation and the assessment), IOCs with verdicts, and recommended actions. Code checks it before it is accepted: every IOC must appear in the evidence, and no recommended action may tell anyone to act automatically. A High or Critical result, or a low-confidence one, is investigated again by the strongest configured model.
  </Step>
  <Step title="It writes back to CoPilot">
    Code restores the customer's tokens to real values, then writes the job, the report and the IOCs through CoPilot's AI Analyst API as a dedicated `talon-analyst` service user, and marks the job completed. The model never calls CoPilot's write-back routes. The customer code always comes from the job, never from the model.
  </Step>
  <Step title="It remembers">
    A summary of the outcome is filed in the customer's memory for the next investigation.
  </Step>
</Steps>

The report then shows on the alert's **AI Analyst** tab, on the AI Analyst page's **Reports** tab, and, if routing is set up, in your [notifications](/power-features/ai-analyst-notifications).

### Shadow, then live

Write-back is set per customer:

| Mode | What CoPilot gets |
|---|---|
| **Shadow** | Nothing. The report stays in Talon, for comparison. Every new customer starts here. |
| **Live** | The job, report and IOCs, as above. |

Turning write-back **off** for the whole deployment is the kill switch: Talon then sends no write to CoPilot for any customer.

A customer goes live only after a shadow period and a comparison of its reports ([Installing Talon](/power-features/talon-install#roll-out-per-customer-shadow-first)). To go live, the customer is assigned to Talon's service user in CoPilot first, then added to Talon's live list.

## Privacy and tenancy

- **Anonymization, per customer.** Before any tool result or alert text reaches the model, usernames, hostnames, email addresses and internal IP addresses are replaced with tokens. Values threat intel needs (file hashes, external IPs, public domains, rule metadata) pass through. Tokens belong to one customer, are stored encrypted, and are restored only in that customer's report and chat replies.
- **Which model providers a customer allows** is part of its policy in Talon (for example, Anthropic only).
- **Tenant binding in code.** Every SIEM query is bound to the customer's verified indices, and every endpoint read to the customer's agents. A request for another customer's data is refused before it is made, whatever the model asks for.
- **CoPilot's own checks still apply.** Talon's service user is an ordinary CoPilot analyst, assigned only the customers it serves. In chat, CoPilot sends the user's own customers and alert tags with every message, and Talon re-checks them on every turn.

## Memory (MemPalace)

Talon keeps long-term memory in MemPalace, an open-source memory service that runs inside the talon-analyst stack, with one area (a "wing") per customer:

- a summary of every investigated alert;
- likely false positives (only from confident, benign reports, never from runs whose input looked like a prompt injection, and never from activity put down to testing);
- the durable and one-off **lessons** your analysts teach it from the [review workflow](/power-features/ai-analyst-review);
- in chat, what a user asks it to remember.

Memory holds the anonymized tokens, not the raw values. Earlier memories are recalled at the start of each investigation for the same customer. CoPilot never talks to MemPalace directly: lessons go through Talon.

With Talon v2 on, the AI Analyst page's **Memory** tab shows this memory per customer, the asset timelines and each user's own chat memory, and lets you forget one-off review lessons and chat "remember" lessons: see [Talon memory](/power-features/talon-memory).

## Threat intel

With the optional threat intel service turned on, Talon can look up public indicators: hashes, external IPs, domains and URLs (VirusTotal, abuse.ch, AbuseIPDB, GreyNoise, urlscan.io), and vulnerabilities (NVD, EPSS, CISA KEV, vendor advisories). Each customer's internal domains are on a deny list, so they are never sent out. Each source needs its own API key; the public VirusTotal API is for non-commercial use, so a commercial key is needed (or leave it empty).

## Chat

The AI Analyst page's **Talon Chat** tab talks to Talon.

- **Without Talon v2:** one conversation per user, with no customer data. It answers general security questions and explains what you paste into it.
- **With Talon v2:** a list of threads. When you start one you pick a customer, or **General (no customer data)**. A customer thread is bound to that one customer for good: it can query that customer's SIEM, Wazuh, Velociraptor and memory (anonymized, as in investigations), and shows each tool it calls. Its history is kept. A thread is archived after 30 days without activity, or once it is 90 days old however active, and an archived thread is deleted 90 days later; SOCFortress can change all three periods for an install, and you can archive a thread yourself.

### The Talon v2 setting

Talon v2 turns on threaded chat, approvals, the usage and cost views, and the automation settings. It takes two steps:

1. On Talon, `TALON_V2_API=true` (SOCFortress sets it during install or later).
2. In CoPilot, an admin turns on the **Talon v2** setting with `PUT /api/talon/v2/settings` and the body `{"v2_enabled": true}`. CoPilot refuses it until Talon's v2 API answers.

With the setting off, CoPilot behaves exactly as before: the v1 chat and the v2 routes answer as if they don't exist.

### Actions with human approval

In a v2 chat, Talon can **propose** an action, but it never carries one out. CoPilot shows an approval card in the conversation and lists pending proposals on the **Approvals** tab. An approver approves or denies; on approval, CoPilot re-checks everything and runs the action itself, as the approver.

| Action | Who can approve |
|---|---|
| Set an alert's status, assign it, comment on it | Admin, analyst, responder |
| Quarantine or release a host (Velociraptor) | Admin, responder |
| Collect a Velociraptor artifact on a host (from a fixed catalogue of read-only artifacts) | Admin, responder |
| Run a PowerShell or bash command on a host, through Velociraptor | Admin, responder |

The card shows exactly what will run: the artifact and its parameters, or the shell and the full command text, with hidden characters made visible. Talon's own Velociraptor access stays read-only; collections and commands need a CoPilot release newer than v0.1.99, and are turned on in Talon by SOCFortress.

### Automation levels

Separately from chat, a customer can allow Talon's **automatic investigations** to run some things on an endpoint without asking. This is set per customer by a CoPilot admin on **Customers → *customer* → AI Automation**, and CoPilot enforces it. With no policy, every level is off.

| Level | What an investigation may run | Available |
|---|---|---|
| 1 | Read-only collections of process, network, service, scheduled-task and startup state, on the alert's own host | Yes |
| 2 | Admin-chosen collections and file collection | Planned |
| 3 | Read-only commands | Planned |
| 4 | Free-form commands | Planned |

Each level has a mode: **Off**, **Shadow** (records what it would have run, runs nothing) or **Auto**. A **Propose** mode is planned. Raising level 3 or 4 asks the admin to acknowledge the risk first.

The guardrails hold at every level:

- only for alerts CoPilot's alert pipeline or an analyst sent, never for Customer Portal requests or replays, and only for customers in live write-back;
- only on a host that is an asset of the alert being investigated, within caps per run, alert, host and customer;
- the strictest setting wins: the customer's policy in CoPilot, the customer's ceiling in Talon, and Talon's deployment-wide maximum (0 by default);
- **AI Analyst → Settings** has the global switch (admins), which stops every automated start for every customer;
- a clean-looking collection never lowers a report's severity.

Automation stays at level 0 unless SOCFortress and you agree on a level for a customer.

## Usage and budgets

With Talon v2 on, the **Usage** tab shows model cost by day, customer or user (a non-admin sees their customers' investigations and their own chat), and an investigation's cost and run timeline appear on its job. Admins set daily and monthly limits per customer on the **Budgets** tab; Talon also has deployment-wide and per-user daily limits. A run over a limit is refused with the reason.

### AI Analyst page

**AI Analyst** in the main menu (`/ai-analyst`):

| Tab | Purpose | Shown |
|---|---|---|
| **Overview** | The [health dashboard](/power-features/talon-health-dashboard): is Talon up, what's degraded, how to fix it | Always |
| **Talon Chat** | Chat with Talon (v1, or threads with v2) | Always |
| **Approvals** | Action proposals waiting for a decision, with a count | Talon v2 on |
| **Memory** | [What Talon remembers](/power-features/talon-memory) per customer, asset timelines, your own chat memory; forget one-off and chat lessons | Talon v2 on |
| **Ops** | [Talon's ops jobs](/power-features/talon-ops): endpoints gone quiet and log sources gone silent; acknowledge, mute, reopen; the jobs and Run now (admins) | Talon v2 on |
| **Usage** | Model cost by day, customer or user | Talon v2 on |
| **Budgets** | Daily and monthly limits per customer | Talon v2 on, admins |
| **Settings** | The global automation switch | Talon v2 on, admins |
| **Reports** | All investigation reports across alerts | Always |
| **Feedback** | Review results per customer ([review workflow](/power-features/ai-analyst-review)) | Always |

### Alert-level integration

When you open any alert in **Incident Management → Alerts**:

1. The **AI Analyst** tab appears next to Overview. If an investigation report exists, it is selected by default and marked with a pulsing dot.
2. Reports show the severity, summary, full report and recommended actions.
3. If an alert has several investigations, a dropdown switches between them (most recent first).
4. The **Investigate with AI Analyst** button on the Overview tab starts a new investigation on demand.

### Customer settings

On **Customers → *customer***:

| Tab | What it sets |
|---|---|
| **AI Triggers** | Whether new alerts are sent to Talon automatically |
| **AI Automation** | The customer's automation levels (admins, Talon v2 on) |
| **AI Report** | What the customer's portal users see and may request (below) |

### Customer Portal

Under **Customers → *customer* → AI Report**, an admin decides what the customer's portal users get:

| Setting | Effect |
|---------|--------|
| **Show AI Analyst findings in the Customer Portal** | An AI Analyst Insights card on the portal Overview and an **AI Report** tab on each alert, both read-only |
| **Let portal users request an AI analysis** | A **Run AI analysis** button on that tab, also to re-run a finished analysis. Needs the findings switch on |
| **Daily limit** | How many analyses the customer's users can request in any 24 hours, or unlimited |

All three start off for a new customer. A request is refused while an analysis of the alert is still running and within 30 minutes of the last one; it is noted on the alert's timeline and in the audit log. The portal never shows the limit: a request over it is refused with a message saying the daily limit has been reached. The panel shows how many requests the customer made in the last 24 hours.

This is independent of **AI Triggers**, which start investigations automatically as alerts arrive: a customer can get analyses on request only.

## Safety and guardrails

- **Treat reports as drafts.** Review them before acting ([review workflow](/power-features/ai-analyst-review)).
- **Read-only by default.** Talon's SIEM, Wazuh, Velociraptor and CoPilot database accounts are read-only. Changes go through CoPilot, after a human approval or within the customer's automation policy.
- **No customer crosses into another.** One customer per run and per chat thread, enforced in code.
- **Simulations are real.** Talon never downgrades severity because activity looks like a test or a breach-and-attack simulation.
- **Roll out per customer**, shadow first, and keep the kill switch in mind: write-back **off** stops every write to CoPilot.
