# CoPilot Prowler runner (`copilot-prowler`)

Runs [Prowler](https://github.com/prowler-cloud/prowler) cloud security scans for
`copilot-backend`, replacing ScoutSuite (#1328; design in the issue). It is
Prowler's official CLI image (`toniblyx/prowler`) plus a small job API.

The backend owns everything product-facing: cloud accounts per customer, their
credentials at rest, schedules, findings in MySQL, tenancy. The runner only runs
scans. It stores nothing of its own beyond a scan's results, until the backend
fetches and deletes them.

## Why a separate container

Prowler can't share the backend's Python environment. It pins about 100 packages
to exact versions, 20 of which clash with the backend's (numpy can't be reconciled
at all: Prowler needs 2.x, the backend 1.26 for `elasticsearch7`). It also keeps
the cloud session in a process-wide global, so one process runs one scan. And full
Microsoft 365 coverage needs PowerShell 7 with the Exchange and Teams modules,
which the official image already has.

## How a scan runs

1. `POST /v1/scans` starts one `prowler` process. It gets its own process group,
   its own environment, and a private directory under `/work` (mode 0700).
2. Credentials reach Prowler through that process's environment, never its
   command line. A GCP key, which Prowler reads from a file, is written there
   with mode 0600 and deleted as soon as Prowler exits. The environment is built
   from scratch: nothing of the runner's own (its token above all) reaches Prowler,
   except proxy settings.
3. Prowler writes OCSF JSON, HTML and CSV reports. A separate process reads the
   OCSF file as a stream and writes:
   - `summary.json`: totals, failures by severity, and per-check counts with each
     check's metadata and compliance mapping;
   - `findings.ndjson`: the FAIL and MANUAL findings, one per line. PASS findings
     are only counted.
4. The OCSF file is then deleted. It carries each resource's raw configuration
   (`resources[].data`), which can hold secrets, and none of it is kept.
5. A scan that runs past its time limit is stopped, with everything it started.
   Exit codes 0 and 3 (failed checks) count as success.

Jobs live in memory, in one uvicorn worker. A restart forgets them and empties
`/work`, credential files included. The backend then gets a 404 for the job and
marks the scan failed.

## API

Every `/v1` route needs `Authorization: Bearer $PROWLER_RUNNER_TOKEN` (at least 32
characters). Without such a token the runner answers 503 to everything, so the rest
of the stack still starts. Every answer is `no-store`. An error is
`{"detail": "<fixed text>", "code": "<code>"}`: no request value, credential or
Prowler message is ever echoed. A 422 names only the fields that were wrong.

| Route | |
| - | - |
| `GET /healthz` | Liveness for Docker (no token) |
| `GET /v1/health` | Prowler's version, PowerShell present, capacity |
| `POST /v1/connection-test` | Runs the Prowler SDK's `test_connection` for the credentials: `{ok, code, message, prowler_error}` |
| `POST /v1/scans` | Starts a scan: `202` and the job. `429 busy` when `PROWLER_MAX_CONCURRENT` scans are running |
| `GET /v1/scans/{job_id}` | `status` (`running`, `normalizing`, `completed`, `failed`, `cancelled`), `error`, `totals`, `logs` |
| `GET /v1/scans/{job_id}/summary` | `summary.json` (`409` until completed) |
| `GET /v1/scans/{job_id}/findings` | `findings.ndjson` (`application/x-ndjson`) |
| `GET /v1/scans/{job_id}/artifacts/{html\|csv}` | Prowler's own reports |
| `DELETE /v1/scans/{job_id}` | Cancels the scan if it is running, then deletes everything it left |
| `GET /v1/compliance/{provider}` | The frameworks this Prowler version maps checks to, keyed like the findings (`CIS-5.0`, `MITRE-ATTACK`) |

A scan request (the connection test takes the same body):

```json
{
  "provider": "aws",
  "auth": {
    "method": "role",
    "role_arn": "arn:aws:iam::123456789012:role/ProwlerScan",
    "external_id": "<generated by CoPilot, one per account>",
    "base_credentials": {"access_key_id": "...", "secret_access_key": "..."}
  },
  "scope": {"regions": ["eu-west-1"]},
  "options": {"excluded_checks": [], "excluded_services": [], "timeout_seconds": 14400}
}
```

| Provider | `auth` | `scope` |
| - | - | - |
| `aws` | `role` (+ optional `base_credentials`; without them, the host's instance or task role), or `access_keys` | `regions` |
| `azure` | `client_secret`: `tenant_id`, `client_id`, `client_secret` | `subscription_ids` |
| `gcp` | `service_account_key`: the key file as JSON (its token URI and other URLs must be Google's) | `project_ids`, `excluded_project_ids`, `organization_id` |
| `m365` | `client_secret`, as Azure | `tenant_domain` (required by the connection test) |

A failed scan's `error.code` is one of `auth_failed`, `permission_denied`,
`wrong_account`, `m365_powershell_failed`, `connection_failed`, `invalid_request`,
`timeout`, `cancelled`, `scan_failed`, `output_invalid` or `internal`.
`error.prowler_errors` lists the exception classes Prowler logged, never their
messages. A scan that completed can still report checks that logged errors (usually
a missing permission) in `logs`.

## Settings

| Variable | Default | |
| - | - | - |
| `PROWLER_RUNNER_TOKEN` | none | Required, at least 32 characters (`openssl rand -hex 32`); the backend sends the same value |
| `PROWLER_MAX_CONCURRENT` | 2 | Scans at once (1–16) |
| `PROWLER_SCAN_TIMEOUT` | 14400 | Seconds before a scan is stopped (60–43200), unless the request sets its own |
| `PROWLER_CONNECTION_TEST_TIMEOUT` | 120 | Seconds |
| `PROWLER_JOB_TTL_SECONDS` | 86400 | A finished scan's results are deleted after this, if the backend hasn't already |
| `PROWLER_MAX_JOBS` | 200 | Scans held at once, finished ones included |
| `HTTP(S)_PROXY`, `NO_PROXY` | none | Passed on to Prowler, the only variables that are |

With the AWS host-role option on EC2, IMDSv2's hop limit must be at least 2 for a
container to reach the instance metadata.

## Tests

```bash
cd prowler-runner
python3.12 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

No Prowler and no network are needed. A fake `prowler` (`tests/fakes/`) writes
`tests/fixtures/aws_sample.ocsf.json`, which Prowler 5.52.0's own OCSF writer
produced (`tests/fixtures/make_ocsf_fixture.py`). The log tests use lines captured
from the real CLI.

## Upgrading Prowler

1. Change `PROWLER_IMAGE` in the Dockerfile (tag and digest).
2. Regenerate the fixture with the new version and run the tests:
   `pip install prowler==<version>` in a scratch environment, then
   `python tests/fixtures/make_ocsf_fixture.py tests/fixtures/aws_sample.ocsf.json`.
3. Check the CLI still accepts the runner's options: run a scan with fake
   credentials and expect `auth_failed`, not `invalid_request`.
